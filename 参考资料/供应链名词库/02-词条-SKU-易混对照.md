## 一、四方对照：SKU / SPU / 平台 SKU / ASIN

### 1.1 四个术语不是一条链，是两条链

**先破一个常见误解**：这四个词常被画成一条四层链（商品 → SPU → SKU → 平台标识）。**不对。**

真正的结构是**两条并列的链**：

```
链 A（卖家内部）      商品 ── SPU ── SKU
链 B（平台目录）      平台商品目录 ── parent ASIN ── child ASIN
                                        ↑
                            两条链在"变体聚合"这一点上功能同构，
                            但身份体系互相独立，谁也不能替代谁
```

**依据（亚马逊官方原文）**：*"an ASIN isn't able to help with product identification outside of Amazon, whereas a GTIN can be used to identify a product no matter its retailer."*（**C 级·平台官方**）
**⇒ 推论 1**：**ASIN 的作用域到亚马逊目录为止。** 它与 SKU 不是上下层关系，而是**两个不同体系的并列身份**——一个属平台，一个属卖家。这与既有文档 §3.1 的「内部身份 vs 对外交付身份」二分**同构**，可互为印证。

### 1.2 四维对照表

| | **SKU** | **SPU** | **平台 SKU** | **ASIN** |
|---|---|---|---|---|
| **谁定** | 企业（或货主）自己定 | 企业 / 平台定 | **卖家在该平台自定** | **亚马逊分配** |
| **作用域** | **企业内部**（既有文档 §1.1 推论 2） | 企业 / 平台内 | 单个平台内 | **亚马逊目录内，且跨站点不通用** |
| **是否标准化** | **否，不受规范**（B 级） | 否 | 否 | 亚马逊单一体系内唯一 |
| **指向** | 最小**库存**单位（"件"） | 商品信息聚合的最小单位（"款"） | 卖家的该平台商品条目 | 平台目录中的**商品条目或变体** |
| **数量关系** | SPU : SKU = 1 : N | —— | 与货品**多对多** | 见 §二 分层结构 |
| **层级感** | 含**销售属性**（颜色/尺码/包装） | **不含**销售属性，只含本质属性 | 由平台规则决定 | parent / child 两级 |

### 1.3 SPU 的定义与判据

**事实（B 级）**：

- SPU（Standard Product Unit，标准化产品单元）是**商品信息聚合的最小单位**，是**由固定属性值对构成的信息集合**，这些属性值对必须满足**可复用性、易检索性**两大技术标准；构成要素包含**品牌、型号、材质**等与商品本质相关的固定属性。
- **核心特征：与商家、颜色、款式等销售属性无关，仅聚焦产品本质属性。**
- 关系：**SPU 区分产品品种，SKU 作为库存计量最小单位。**
- 来源：百度百科「SPU」· 快懂百科「SPU」· 中文百科全书「SPU」（**三条表述一致**）

**判断边界的三条实用规则（C 级，仅作线索）**：判断两个商品是否同一个 SPU，通常看——① 型号或系列是否相同；② 基础功能是否一致；③ 是否能用同一个商品页覆盖。**若必须在平台单独建 Listing 才能讲清差异，大概率不属于同一个 SPU。**
来源：某电商系统厂商文章（C 级）。**仅作线索，不作依据——待 B 级以上来源替换。**

**⇒ 推论 2**：**"属性值完全相同"是判定同一 SPU 的充分条件**（百度百科原文："属性值的完全一致性是判定同一 SPU 的必要条件"）。**这意味着 SPU 的边界由属性模型决定——属性模板不同，SPU 的切法就不同。** 同一批货，在两个属性模型不同的平台可以被切成不同数量的 SPU。**这是 §二 平台差异的根因。**

### 1.4 一个值得记的第三层：CSPU

**事实（C 级·平台规则文件）**：政采云平台的术语体系里，**CSPU（Child SPU）** 是"在 SPU 的基础上**精确到具体销售规格**的信息"，与 SPU 统称"标准商品模板"。同体系的 SKU 被定义为"**销售单元**"——供应商管理商品库存进出的基本单元。
来源：浙江省电子卖场平台规则文件（C 级）。

**⇒ 观察（推论）**：**"SPU 之下、SKU 之上"还存在中间层的做法，不止一家。** 亚马逊用 **parent / child ASIN** 表达同一件事，政采云用 **SPU / CSPU**，天猫系的"商品 / 单品"也有类似的层。**这说明变体聚合是全球电商的共性问题，各平台各自命名，没有统一术语。**
**⇒ 对本项目的意义**：**不要试图用某一平台的术语去定义本项目的模型**——这正呼应既有文档 §3.1「货品是仓内部身份、标识是对外交付身份」的分法。

## 二、平台对「变体 vs 独立商品」的分组规则不一致

### 2.1 亚马逊官方给的结构（C 级·平台官方）

**事实**：

- ASIN 是 **10 位字母数字**的唯一组合，由亚马逊分配给在亚马逊站内销售的商品，**包括商品变体和商品版本**；出现在商品详情页上，也可在卖家中心用于库存管理。
- **同一商品在不同亚马逊站点可能有不同 ASIN**（如 `amazon.co.uk` 与 `amazon.com`）。
  - 官方原文：*"The same product might have different ASINs in different Amazon stores, such as amazon.co.uk vs. amazon.com."*
- **parent / child ASIN 结构**：**parent ASIN 是搜索结果中展示的商品，但它本身"不可购买"（non-buyable）**，其作用是让亚马逊目录在子商品之间建立关系；**child ASIN 才是承载具体规格（尺寸、颜色等）的可购买变体**。
- 官方对 SKU 的表述：*"mostly created by companies to monitor their own inventory, so **the same product at a different company can have different SKUs**."*（**逐字印证既有文档 §1.1 推论 2**）

### 2.2 跨平台的不一致（C 级，仅作线索）

**观察（C 级来源，仅用于发现线索，不作依据）**：各平台对以下四点**不一致**——

1. 颜色 / 色号变化，是**新建 listing** 还是**留在同一 listing 内**；
2. 包装规格与**多件装**是否与单件归在一组；
3. **套装（bundle）**是否算独立商品；
4. **同一货物的不同卖家 listing** 是否算不同条目。

**⇒ 结论（推论）**：**同一物理商品范围，在天猫可能是一个 listing，在抖音可能是多个。** 因此——**跨平台的"商品数量"对比，必须先做归一化规则；不做归一化的计数，测的是"各平台的列表页约定"，不是"商品数量"。**

## 三、跨平台计数的归一化

**事实（C 级，仅作线索）**：有一条判断值得记——**一个 SPU 下通常没有单一价格**（一个 SPU 跨三种规格就有三个价格），因此**任何 SPU 层的均价计算都必须先声明用哪个规格代表它**；**价格工作必须在 SKU 层做。**

**由此得出三条操作规则（推论）**：

| # | 规则 | 理由 |
|---|---|---|
| 1 | **任何"有多少个商品"的陈述，不写明层级即无意义** | "1,200 个商品"与"1,200 个变体"是两个不同断言 |
| 2 | **价格分析只在 SKU 层做** | SPU 无单一价格，均价需先做代表规格假设——而该假设常不被声明 |
| 3 | **层的选择由问题决定**：选品宽度 / 陈列 → SPU 层；动销 / 复购 / 商详健康度 → SKU 层 | 层级混用会导致结论反转 |
| 4 | **跨平台对比前，先问对方"变体怎么分组"** | 各平台约定不同，问清楚优于假设 |

**一条可用于说明危险的例子（C 级来源原文所述情形）**：两个品牌各出 10 款产品，A 每款 8 个色号、B 每款 2 个色号——**在 SPU 层两者宽度相同；在 SKU 层 A 是 B 的四倍。** "A 的品类宽度是 B 的四倍"这句话**在 SPU 层为假、在 SKU 层为真**，而两种说法都会被人自信地说出来。

**反方 3｜我用"两条并列的链"否定"一条四层链"，但这个否定是我自己造的框架，没有来源。**

**反方 4｜§2.2 的"四点不一致"来自 C 级来源，我不能采信，却又写进了正文并据此推出"跨平台计数必须归一化"。**
