> ### 1.4 产品边界：只做三方云仓（v2 新增，v5 定论）
> Martin 于 2026-09-12 裁定：**卖给工厂的不划算，不如卖 MES，还是专心搞云仓。**
>
> | 类型 | 生意性质 | 是否纳入 |
> |---|---|---|
> | 电商仓、存储仓 | 三方云仓：**替别人保管** | **纳入** |
> | 工厂仓、原料仓、物料仓 | 工厂内部仓储：**管自己的料** | **不纳入**。这是 ERP 与制造执行系统的地盘 |

而若依 WMS 的**单据类型字典**（`script/sql/wms.sql:183-192`，代码事实，不是我的推断）：

| 字典 | 实际取值 |
|---|---|
| `wms_receipt_type`（入库类型） | **生产入库** / 采购入库 / 退货入库 / 归还入库 |
| `wms_shipment_type`（出库类型） | 退货出库 / 销售出库 / **生产出库** |

**「生产入库」「生产出库」是生产工单驱动的出入库。** 这正是 `01 §1.4` 判为"不纳入"并写明理由的那一类——理由原文：工厂内部仓储的价值不在保管，在**与生产计划咬合**。

**推论（附依据）**：若依 WMS 的业态口径落在工厂仓一侧，不是云仓一侧。

**所以：把你三周前亲手划死的边界，交给一个踩在边界另一侧的系统去重新定义——这两件事不能同时成立。** 要么作废 §1.4，要么这次选择不成立。这条必须先答。

## 三、去掉文案水分后，这系统真实的样子（全部以代码为准）

**菜单**（`wms.sql` 的 `sys_menu`，权威来源）：

```
入库     出库     移库     盘库     库存统计     库存记录
└─ 基础数据 ── 往来单位 / 仓库管理 / 品牌管理 / 商品管理
```

**规模**：业务模块 16 个控制器。主数据 4 类（仓库 / 库区〔仅 advance〕/ 商品 + SKU + 品牌 + 分类 / 往来单位）。单据 4 种（入库单 / 出库单 / 移库单 / 盘库单），各三态（暂存 / 作废 / 完成）。

**与云仓定义的距离**（下列是"没有"，不是"弱"）：

- **零货主**。`master`、`advance` 的 Java 代码中 `货主|owner|tenant` 全部零命中；建表脚本 `tenant` 字段零个。
  库存表原始字段：`wms_inventory(id, sku_id, warehouse_id, quantity, remark, 4 个审计字段)` —— **没有货主、没有批次、没有效期、没有库位**。
  往来单位表原始字段：`wms_merchant(..., merchant_type, merchant_level, bank_name, bank_account, contact_person, ...)` —— **是客户/供应商档案，不是货权主体**。
- **零计费**。无仓租、无操作费、无增值服务费、无结算单。
- **零时效**。无收货上架时效、无出库及时率、无异常响应。
- **零设备**。16 个控制器无一个条码 / PDA / RFID / 自动化设备入口。
- **零留证**。无影像、无留痕。
- **零唯一约束**（上一份报告已核：两分支 37 张表，`UNIQUE KEY` 零条）。

**对照 `01 §2.2` 的三条目标**：库存准确率（可承载）／时效达成率（**无承载**）／单位操作成本（**无承载**）。若依 WMS 只装得下第一条。

## 五、四条路线（红队：我不推荐哪条，因为我不知道"我们"是谁）

> 原为「三条互斥路线」。D1 答后**路线三作废**；D2 答后**路线一与路线二不再互斥**，合为**路线四**。以下三条保留原文，供回溯。

### 路线一｜换底座：拿若依 WMS 当代码起点，改造成三方云仓

- **适用条件**：许可证允许（多租户须先拿到书面授权）；接受库存主键与全部单据口径重建；接受 Sa-Token + Vue3 + Element Plus 技术栈。
- **代价**：README 里那些"免费即得"的卖点全部落空——改造量约等于重做库存与单据全链。
- **崩的条件**：若"一仓 N 货主"按许可证定义构成多租户，此路**在法律上直接堵死**，不必谈技术。

### 路线二｜换定位：产品从三方云仓转向工厂 / 自营仓

- **适用条件**：承认 `01 §1.4` 作废；放弃"操作费 − 人工 − 差错"这套利润逻辑；接受不做计费。
- **好处**：若依 WMS 功能面几乎即插即用，需求文档可大幅压缩。
- **崩的条件**：**客户为什么要买一个已经免费开源的、功能相同的东西？** 差异化归零，买断 + 年服务费的标的不复存在。

### 路线三｜自用：这软件给自己工厂用，不对外卖

- **适用条件**：仓库是自有仓、货主是自己。
- **好处**：与 README 功能面**完全吻合**——不需要货主、不需要计费、不需要多租户，第四节三条结构性冲突自动消失。
- **代价**：`CODEBUDDY.md §一` 整体改写；现有 5 份文档作废。
- **声明**：这条能解释你这句话里所有反常之处，但**是我猜的**（依据：你运营自有工厂）。若不是，这条作废。
### 路线四｜双线并进：云仓线 + 工厂线（D1 + D2 合起来的落点）

> ⚠️ **本条已作废（2026-09-25 10:07，D7）。** 工厂线整体放弃，只剩**路线一**与**路线二**（路线二亦随 D7 排除 —— 它就是工厂线）。

## 五·补｜D1 =「对外卖」之后的推论与矛盾

### 1. 这一答确认了什么、没确认什么

**确认的（推论，依据：`CODEBUDDY.md §一` 原文）**：D1 与现行「私有化交付，买断 + 年服务费，不做 SaaS」**一致**。这条**不用改**。

**没确认的（事实）**：`CODEBUDDY.md §一` 里有两块内容——**交付形态**（私有化买断 + 年服务费、不做 SaaS）与**产品定位**（三方云仓、一仓 N 货主、货权分离、重量款、人工 + 手持终端、预留自动化接口）。**D1 只覆盖前者。后者一个字没动。**

**排除的**：路线三（自用）作废。第五节那三条互斥路线，剩路线一（换底座）与路线二（换定位）。

### 2. 「对外卖」这个答案本身，有三条真反对

**反对 1｜「对外卖」与「若依 WMS 才是我们真正需要的」组合起来，在路线二下自相矛盾。**
要卖的软件，跟一个**免费开源、功能面几乎相同**的软件，凭什么收买断费 + 年服务费？只剩两种活法：
- **卖人**（私有化部署 + 实施 + 二次开发 + 年维护）→ 护城河是**交付与售后能力**，软件本身不是卖点。此时 `01`/`02`/`04` 里那些领域模型（货权分离、计费口径、留证口径）是**唯一可能变成产品护城河的东西**——丢掉它们，剩下的生意本质是卖人力。
- **卖「改得比他好用」** → 那是路线一，不是路线二。

**反对 2｜D1 没回答「卖给谁」，而这是比「卖不卖」更实质的问题。**

| | 三方云仓运营者 | 工厂 / 自营仓主 |
|---|---|---|
| 收入结构 | 操作费 − 人工 − 差错，对「少扫一次码」极度敏感 | 仓储是成本中心，不产生收入 |
| 免费开源能否覆盖其需求 | **不能**（无货主 / 无计费 / 无隔离） | **能覆盖大部分** |
| 付费理由 | 货主隔离、计费对账、差错留证 | 弱。真正的痛在「与生产计划咬合」，属制造执行系统地盘 |
| 与 `01 §1.4` 的关系 | **正是该节定义的目标客户** | **正是该节排除的对象** |

「外」是左边还是右边，D1 没答。**这两类客户的钱包和决策链不通，系统要装的东西也不通。**

**反对 3｜「对外卖」这三个字，在今天这个语境下最容易被误读成「定位不用改」。**
不会。§一 的交付形态成立，不等于产品定位成立。**定位问题原样悬着，就是 D2。**

### 3. 路线二的一个可行变体（红队备选，不是推荐）

若 D2 选「转向工厂仓」，路线二有一种活得下去的样子：**不卖软件，卖交付**——私有化部署 + 按需二次开发 + 年维护，客户是「想上系统、但没有 IT 能力、也不打算自己部署开源」的中小工厂。
- **它的前提**：承认护城河在服务能力，不在领域模型。这与 `01 §1.4` 的排除理由不冲突（那节说「做出来也是残缺的 MES，卖不过 MES」——而这条路卖的本来就不是 MES 级功能，是「能跑起来、有人管」）。
- **它的崩点**：一旦客户知道自己能免费拿到同一套东西，或一旦有第三家以更低价格做同样的部署服务，价格立刻塌。

### 4. 一处自我修正：许可证那条，我上一轮说重了

更早那份项目分析报告里，我把许可证的多租户条款说成与「一仓 N 货主」**正面撞上**。**这个判断给重了，现降级。**

理由：`LICENSE` 原文用的是 `operate a multi-tenant environment`，即**运营一个多租户环境**。这个短语在开源商业许可里通常指**一套实例服务多个客户**（SaaS 化运营）。而「一仓 N 货主」是**业务内部的货权分离**——部署上仍是每个客户一套私有化实例。

**这两者是不是同一件事，我没有依据，是猜测。** 但它至少是两种读法，而我只写过一种，还用了断言级措辞。

| 读法 | 含义 | 对路线一的影响 |
|---|---|---|

### 4. 三条技术问题（其中一条必须你定）

**A. 记账基准：库存只能以基本单位记。**
「1 卷 = 50 米」。库存**必须只以基本单位（米）记账**，辅助单位（卷）只用于**录入与展示**。否则「出 3 卷零 10 米」两笔账无法合并对账。**这是会计原则，不是设计偏好。**

**B. 换算率挂在货品级还是批次级？（D12，必答）**

- 长度型（面料）：换算率稳定 → 货品级固定值够用
- **重量型（化工 / 钢材）：实际重量随批次浮动**（标称 25 公斤 / 桶，到货 24.6 公斤）→ **货品级固定换算率会让账累积性失真**

**你的「桶」是重量型还是容积型，决定换算率能不能挂在货品上。** 这条我判断不了。

**C. 拆包 / 拆卷 / 倒桶是否算「加工态变化」？（D13）**
