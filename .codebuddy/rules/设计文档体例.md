# 设计文档与字段表的施工体例

> 本文件管「改 `设计文档\` 与 `表字段设计\` 里的文件时怎么改」。**对话行为与文档身份纪律在 `CODEBUDDY.md`，不在此重复。**
> 编排原因：这些口径此前散在各文档头部、`README.md` 与工作日志里，**没有成文位置**——改文档时只能靠翻旧文件模仿。

- 格式：`` `01-业务蓝图.md` **v12** ``（版本号加粗）。
- **`01` 升版后必须回头核对下游文档的「上位依据」是否标了新版本。**

> **⚠️ 已知过期（2026-09-26 实测）**：`02-1` · `02-2` · `04` 三份的上位依据都写 **`01` v11**，而 `01` 已到 **v12**。**未改**——因为「本文写于 v11 时代」可能是有意的语义，改与不改由 Martin 定。

## 三、锚点引用语法（全库在用，此前无成文定义）

| 写法 | 指什么 |
|---|---|
| `01 §2.3` | 文档编号 + 节号 |
| `02-1:106` | 文件**行号**，用于精确指向某一行 |
| `02-1 §3.3 C3b` | 节号 + 条款 ID（`02-1` 的 C 系列校验条款） |
| `场景 7` · `反方 19` · `推论 2.5.5` | `01` 的场景 / 反方 / 推论编号 |
| `01 约束 4` | `01` 的公理 / 约束编号 |
| `U17` · `W8` · `Q4` · `D13` | 未决项编号，按文档分配（见第四节） |

**硬规则：**

1. **编号是全库引用的锚，改文件名不得改编号**（`README.md` §三）。
2. **改条款序号会断引用**——必须先全库搜该序号的全部引用，一并改。
3. **引用上游一律写「文档编号 + 节号」，不写文件名全称**（文件名会随体例变动，编号不会）。

## 五、字段表（`表字段设计\`）

**体例全文在 `表字段设计\00-表结构总览.md` §四「全局约定」，不在此复述。改字段表前读它。**

三条最易违反、单独提醒：

1. **表名与文件名一致，无编号前缀**（与 `设计文档\` 的 `编号-名称` 相反）。
2. **默认值只填技术性默认**（主键自增、时间戳系统写入），**业务默认值一律留空**。
3. **全局字典表不带货主标识**（共 5 张），**货主级表受数据隔离约束，全局表不受**——两者性质不同，不得混同。

---

## 六、交付物通用

1. **任何 Markdown 交付物末尾固定两章**：反方审查（≥5 条）+ 未决项。要求见 `CODEBUDDY.md §2.1`。
2. **未决项必须先判断它属于哪份文档的身份**，再决定写在哪（`CODEBUDDY.md §三`）。
3. **字段出处不在项目内时**（如法定计量单位、行政区划代码），**在说明里写明外部来源，不自造取值**。
