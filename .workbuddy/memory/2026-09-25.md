### 关于若依 WMS 的关键判断（对本项目有直接价值）

- **它是「单货主自营库存台账」，不是「一仓 N 货主的三方云仓」**。`wms_inventory` 主键仅 `(sku_id, warehouse_id)`，**无货主 / 无批次 / 无库位 / 无库存状态**。`wms_merchant` 字典为 `0 客户 / 1 供应商 / 3 客户供应商`，是**往来单位不是货主**。→ **其库存在模型层无法表达货权分离，这是结构缺口不是配置问题。**
- **全项目零条码、零设备接口**（前端 `jsbarcode`/`qrcode` 只用于展示打印），无 PDA 作业闭环。与本项目「人工 + 手持终端、预留自动化接口」的定位完全不同量级。
- **两分支均无「货架/库位」表**，`lite` 连「库区」都没有（`advance` 才有 `wms_area`）→ 仓库描述里「仓库/库区/货架管理」是虚的。
- 优点确有一条实的：`wms_inventory_history` 记「变更前 + 变更后 + 来源单据」，库存可审计；`InventoryService` 单点收口四类单据的库存变更；出库负库存硬拦截（409）。
- 缺陷：`InventoryService` 的「查询-判断-写入」无锁无版本号（Redisson/Lock4j 引了但业务层未用）→ 并发出库可写负库存；盘点差异直接改写库存无审批；四套单据代码同构复制未抽象。
- **许可证硬约束**：改写版 Apache-2.0 附加两条——**不得用于多租户环境**（除非书面授权）、**不得移除 LOGO/版权**；并声明外观设计专利保护。**「一仓 N 货主」正是多租户形态，与本项目冲突，需法务确认。**

## 追问「允许一个 SKU 有多个货主么」——答案与一个真冲突（2026-09-25）

### 三层答案（已定）

1. **一条货品档案记录只能有一个货主**（唯一键＝货主×货品编码，`memory 09-15` 裁定 3）。理由三条均非偏好：约束 4 数据隔离（货品清单是货主对外可见面）· 2.3.1 按货主切片 · B 级事实「SKU 编码不受规范约束、企业自定」⇒ 两货主各自用 `A001` 是常态。
2. **同一个实物商品可以有多个货主**，就是 N 条独立档案。A/B 级事实（`_research\电商仓储与库存管理-共识性说明.md §1.2`，来源 GS1/维基）：**厂商条码（UPC/EAN/GTIN）标识「商品」不标识「归属」，两个货主卖同款货贴同一个码。**
   → **硬推论：厂商条码列可做索引，绝不可做唯一约束**（加了唯一第二个货主建不了档）。它就是 09-15 留下的「扫得出商品、定不到货主」那一型。
3. **若「多个货主」指归属方之外的三位**（下单方 / 结算方 / 看数方）→ **允许，且 U3 已定必须能表达**（§3.3 代运营场景）。

### 本轮新发现的真冲突（须 Martin 拍板）

**这与「货品档案带一个不可变的货主字段」直接打架。** 三种解法各有代价：
- 货品档案不换 → 库存（货主=仓）指向 A 的货品档案，归属方与档案货主不一致，模型自相矛盾；

- 货主字段可变 → 撞（货主×货品编码）联合唯一，且破坏「编码一经使用不得改指向」。
