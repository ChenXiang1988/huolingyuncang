## ★ Martin 裁定（2026-09-15，业态事实）

**原话**：「**无预报到货对于仓库来说是常态事项，直接仓库创建一个到货通知单就好了**」

**解读（两句，缺一不可）**：
1. **定性**：无预报到货 = **常态事项**（不是异常）—— 直接关闭上一轮未决项 1。
2. **路径**：**由仓自己创建到货通知单** —— 不要求货主补发、不走异常通道。

**这条裁定同时解掉了我上一轮反方 2 的风险**（我担心"到货通知可缺"被实现者读成"可不做到货通知"）。裁定的准确表述是：**可省的是货主那一侧，仓这一侧必须建。** 比"可缺"精确。

**它带出四件 01 现在没有位置放的事（待补，未落地）**：
1. **到货通知单的创建方不唯一** —— 货主可建、仓可建。创建方成为单据的一等属性，且**仓自建的单必须对货主可见**（依据：U4「费用账必须可见」的同类逻辑 + 2.3.3）。
2. **同一批货可能出现两张通知单**（仓先建一张、货主迟到的单再来一张）。系统必须能表达"多张单指向同一次到货"，且**迟到单只能挂关联、不得改已入库的账**（实收单是不可改的凭证）。
3. **仓自建场景下，留证的证据效力被削弱**——单据与实收单由同一方产生 = **自证**。⇒ 此场景留证强度必须更高（影像 / 称重 / 时间戳），且必须当场推送货主确认。**这是反方 13「留证撞约束 9」的加强版**，不是新问题，但强度要求要单列。
4. **推论（待确认）**：若无预报到货是常态，则"到货预约（排月台 / 排人力）"的价值下降 —— 仓建单时货已在门口，来不及预约。**⇒ 目标 B（时效达成率）不能靠"预报"保障，只能靠仓内作业弹性。** 连带：物理空间层级需要能表达**待处理 / 待检区**（货到了没计划、没库位时的临时落点）。

**提醒（防实现走偏）**：**"常态" ≠ "可简化"。** 无预报到货既然是常态，就必须有完整的正常流程（留证、编码、回传货主），不能因为"没单"就降低记录要求。

## ★ Martin 裁定 2（2026-09-15，业态事实）— 规则：未认领货物权归仓

**原话**：「**不认就是无主的货品，这个货权直接归属仓库，有赚不亏**」（回答的是"仓自建单后货主长期不确认怎么办"）

**这条是把 §3.5「货权的被动转移」里「弃件」那一类的触发条件具体化了**（§3.5 原四类：留置 / 弃件 / 赔付取得 / 代垫代购；「弃件」原定义 =「退货件 / 无主货长期无人认领」）。**它不是新增第五类**——是给"弃件"补上了一条明确的判定路径与责任方：**由仓主动发起，依据是货主对仓自建的到货通知单不确认。**

### 我当场指出的三个问题

**问题 1（最重要）：「不认」必须先拆成两种，混在一起会出大事故。**
- **不认数量**（"我没发这么多"）→ **是数量争议，货权仍是货主的**。把这种情形也走"归仓"，等于**单方面把有主物变成无主物**。
- **不认货**（"这批货不是我的"）→ 这才是放弃所有权的意思表示。
- 只有第二种才可能触发归仓。**必须在 01 里把这两句写死。**

**问题 2：法律路径走不通「无主物」这条，必须靠合同条款。**（来源：《民法典》条文，见下）
- **第 318 条**：遗失物自发布招领公告之日起**一年内无人认领的，归国家所有**。⇒ **我国无主物归国家，不归保管人。**
- **第 312 条**：遗失物通过转让被他人占有的，权利人有权追回，或自知道受让人之日起 **二年内**请求返还原物。
- **第 322 条**：因加工、附合、混合产生的物，**有约定的从约定**。
- 另有律师解读：**我国不承认先占制度，"无主物归公"**（来源：国浩律师(广州)事务所解答，权威性中等，需法务复核）。
- ⇒ **推论：仓单方面把"货主不认的货"认定为无主物并归自己，法律依据很弱。这条只能靠《仓储合同》里明确约定"逾期未认领视为放弃所有权"来落地。** 产品能做的是**执行条款 + 留痕 + 走流程**，不是自己实现归属。
- ⚠️ **法律结论需法务确认，我不是律师，以上只到"条文事实 + 推论"一级。**

**问题 3：「有赚不亏」在三种情形下不成立。**
1. **仓没有销售渠道** —— 01 §1.4 明确不做自营、不做销售。**有货权 ≠ 有变现能力**，只能折价甩卖。
2. **低值货 / 必须报废的货** —— 处置的人力与合规成本可能高于货值，是净亏。
3. **若法律上最终归国家，仓一分钱拿不到**（承接问题 2）。
⇒ **"不亏"这一半站得住（比白干强），"有赚"这一半的前提是"有变现渠道"，与 §1.4「不做自营」直接冲突。**

### 连带要求（待补，未落地）

- **前置条件：仓必须能证明自己履行过通知义务**（催告留痕）。否则货主一句"我没收到通知"，整个归仓链条崩塌。**产品必须记录：什么时候通知、通知了几次、货主有没有回应。**
- **道德风险要防**：归仓规则会给仓"不积极催告"的激励（不催，货就是自己的）。**用催告留痕对冲，并设最短期限。**
- **逾期期限必须可配**（撞约束 6 的配置逻辑），且起算点要写死（从第几次通知起算）。
- **归仓时点前后的费用归属是断的**：之前占库位产生的仓租记货主（货主不认 → 变坏账），之后记仓自己。**中间要不要做账务切分，是商务问题。**
- §3.5.4 已定：处置**必须走独立处置单据，不得直接出库** —— 这条继续有效，**没有解决"处置出口是什么"**（报废 / 回收 / 退还 / 折价变卖？）

## ★ Martin 补充（2026-09-15，对裁定 2 的判定入口）

**原话**：「**货品上都是有 SKU 信息的，如果没有 SKU 信息，那么本身就关联不到对应的货主，那就是无主之物。**」

**他给的判定链**：SKU 信息 → 关联货主 → **有主**；无 SKU → 关联不到货主 → **无主之物**。

### 我当场指出的缺口：`SKU → 货主` 这个映射不是必然的

**取决于 SKU 属于哪一层级的编码：**
- **厂商原码（UPC / EAN 这类）** —— 标识的是**商品**，不标识**归属**。两个货主卖同一款货，货上贴的是**同一个码**。
- **货主自建编码** —— 才与货主绑定。
- 另有第二个变量：**主数据是"一货主一档"还是"跨货主共享货品档"**。若共享且用厂商原码，**扫码会撞码**。
- ⇒ **"有 SKU 就能定位货主"只在"货主自建码"或"一货主一档"时成立。** 三方云仓里厂商原码是常见情形，**这条不能当必然**。（属推论，需 Martin 确认业态）

### 更根本的一条：三件事不能等同

| 层面 | 问题 | 结论 |
|---|---|---|
| 系统层面 | 能不能识别 | 识别不到 ≠ 没主人 |
| 事实层面 | 有没有主人 | 权利不因系统没建档而消失 |
| 法律层面 | 权利人是否放弃所有权 | 需明示 + 合同 + 程序 |

**⇒ 推论：识别不到只能推出"暂不可归属"，推不出"无主"。中间至少还差三道：先反查线索（批次 / 箱唛 / 随货单 / 上游通知）→ 挂待认领 + 公示 → 合同有约 + 期满。**

**"无 SKU"在仓内实际是四种，处理路径不同**：① 有厂商码、无货主码（能扫出商品，定位不到货主）② 有条码但不在主数据里（未建档）③ 完全无标识（裸货）④ 标识污损 / 被撕。**01 场景 1 现有的"无条码 → 建档兜底"只覆盖了第 ② 种。**

### 连带硬要求

**无标识货的留证强度必须最高**：连"它是什么"都说不清时，影像 / 包装描述 / 件数记录是**唯一能证明"当初收到的是这批货"的东西**。这是 §7.8 在无标识场景下的加强档。

## ★ Martin 裁定 3（2026-09-15，业态事实）— 货主内货品编码不得重码

**原话**：「**同一个货主SKU不能相同，不然仓执行难度极高**」

**这条关闭了上一轮未决项 1**（货品档案按货主分开建，还是共享主数据）——**答案：按货主分开。**

**模型含义**：货品编码的唯一键是「**（货主 × 货品编码）联合唯一**」，**不是全局唯一**。跨货主**允许**重名（甲货主有 A001，乙货主也可有 A001），**同一货主内不得重码**。

**他给的理由是作业可行性**：同货主内重码，仓管员无法判定该收 / 该发哪一个。

### 这条管不到的四种情形（本轮当场指出，均未落地）

1. **物理条码不唯一 ≠ 货品编码重复。** 编码唯一是**数据层**规则，管不到**货上贴的码**。两个货主编码各不相同，货上仍可能都贴**同一个厂商 69 码** ⇒ **上一轮"扫得出商品、定不到货主"那一型（①有厂商码无货主码）依然存在，没被这条解决。**
2. **"不得重码" ≠ "不得复用"。** 货主停用 A001 后把 A001 再给一个新货品 —— 历史流水里 A001 指向旧货，**追溯断裂**。需单列：**编码一经使用不得改变指向**（变更须走新旧码映射，不得原地改）。
3. **规则前提是上游数据干净。** 货主自己送来重码（他们主数据里就重）是常见情形。仓要么拒建、要么在仓内加区分符，**但不得改货主原码**（否则对不上货主的账）。兜底规则缺位。
4. **手段与想要的效果之间有缺口。** 他要的效果是"降低仓执行难度"，但**光有编码唯一不够——作业界面上货主上下文必须常驻可见**。两个货主各有 A001 时，界面不带货主照样分不清。**⇒ 数据规则（编码唯一）+ 界面规则（货主常驻）两条都要，缺一不成立。**

### 术语污染（必须在 01 钉死）

**"SKU"这个词在 01 里已指两个不同层级的东西**：
- §2.1.6「消耗来源指向任意 SKU」→ 指**货主的货品编码**（内部身份）
- §2.1.8 / 场景 10「平台 SKU 标签」→ 指**平台侧标识**（外部身份）

**Martin 本次说的 SKU = 货主的货品编码（内部身份）。** 两者混用会直接撞崩 v10 的裁定（"标识挂订单、不挂库存"）——若把平台 SKU 当货品编码，库存就必须按平台拆账，而 v10 已明确排除这条路。

### 累积待改（仍未落地，等「落地」）

本轮新增：**场景 1 补「按货主分别建档 + 货主内编码唯一 + 编码不得复用 + 上游重码兜底」**；**§2.1.6 / §2.1.8 统一术语**（内部身份称"货品编码"，"SKU" 只留给平台侧标识）。前几轮待改项：约束层补入库侧上游对接、场景 2 补单据列并重定性无预报到货、§3.5 弃件补判定路径与催告留痕、场景 1 扩无标识四型、§7.8 加无标识最高留证档、§9.1 拆上游来源与单据两行、00 台账补三条裁定。

## 调研：「一品多商」在行业内怎么处理（2026-09-15，Martin 提问）

### 术语先澄清（重要）

**「一品多商」的行业标准含义 = 一个商品有多个供应商供货**，属**零售 / 商超采购**语境（来源：思迅 SaaS 官方文档、商业之星 V7 培训教程、意飞帮助文档）。两种管理法：**单货号法**（一个货号 + 主供应商 + 若干辅供应商，库存合并）／**多货号法**（每供应商独立货号）。

**这套东西在货灵云仓不适用**——它属于**采购**，而 §1.4 已定不做自营；**货主不是供应商**。
三方云仓借这个词指另一件事：**同品不同主**（C-WMS 用语）／ 多货主同 SKU。

### 行业实际做法（事实，来源随附）

1. **库存账绝不合并** —— 万里牛「同一个 SKU 如果同时属于 A 货主和 B 货主，**必须按「货主 + SKU + 批次」维度分别建立库存记录，不能合并成一条总库存**」；通天晓「库存记录必须按「**货主 + SKU + 库位 + 批次**」四维记账，同一个 SKU、同一个库位，不同货主的库存分开计数」；Xorosoft 英文「two customers can use identical item codes **without combining their available inventory**」。
   ⇒ **与 01 §2.1.1 吻合，这一条不需改。**

2. **归属判定在收货那一笔建立，不能事后补** —— 紫鲸物联「商品条码相同时，**收货时按到货通知单的归属自动挂到对应货主名下，而不是靠收货员现场判断**」；Xorosoft「**ownership exists inside the transaction rather than being reconstructed later for reporting**」，并举例：收货员扫 300 件却没识别货主，**歧义在那一刻就产生了**。
   ⇒ **重要修正**：我前几轮把到货通知单定位为"预报"，**不完整** —— 它同时是**货主归属的载体**。**连带**：无预报到货（仓自建单）时，归属由**仓在收货当场指定并留证**，不能事后反推。

3. **物理层 = 物理隔离 ↔ 逻辑隔离的取舍** —— 万里牛三档（完全混放 / 按货主分区 / 按品类分区）；知行合一云仓三档（专属独立库区 / 专属货架库位 / 逻辑隔离共享库位）。**两家三档不是同一划分维度，不能合并成一张表**（我第一版想合并，属过度归纳，已自我纠正）。**对"同品不同主"这个具体问题，万里牛的第二档（按品类分区）无效** —— 同品即同品类，按品类分区等于把它们放一起。C-WMS 明确：「不同货主如有 SKU 相同的情况（例如两家品牌方都卖同一款矿泉水），**需划分独立不相邻的存储区域**」。

4. **作业与盘点按货主维度切** —— 波次 / 拣货任务 / 盘点计划按货主组织，**避免一张拣货单跨货主混拣**；**同一时段只对一个货主封账盘点**，防差异互相污染；**上架时库位与货主绑定，跨区上架系统直接拦截**（来源：紫鲸物联、C-WMS、通天晓）。

### 核实出的 01 三处缺口（已逐条读原文，非推测）

- **场景 3 上架**：节点只写"库位分配（容积 / 承重 / 楼层 / 动线）"，**没有货主维度的库位约束**（行业做法是"跨区上架直接拦截"）
- **场景 5 盘点**：节点与异常**均未提货主**（行业做法是"分货主封账盘点"）
- **场景 6 波次拣货**：波次规划只提"楼层与路径"，**未提按货主组织**（行业做法是"不跨货主混拣"）
- **已对的**：场景 4「跨货主移库（必须不可表达）」、场景 7 复核"（品/量/**货主**）"
