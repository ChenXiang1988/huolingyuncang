## 需求审查：视频监控接入（打包 + 收货环节佐证留痕）—— 本轮未落地

**Martin 原话**：「必须接入视频监控……打包和收货的关键节点自动关联并调用视频监控，生成可作为证据保存的记录；同时针对监控画面输出精确到动作级别的场景描述……确保描述具备可追溯性与举证效力。」

### 我当场指出的错误命题

**把「AI 对画面的文字转述」当成了有举证效力的东西。** 证据法上描述属**传来证据**，证明力远低于原始视频本体；更糟的是**描述一旦与画面不符，会成为攻击整个记录体系的支点**（"你的记录和视频对不上，那所有记录都不可信"）⇒ 错误的描述不是无效，是**负资产**。

**正确的证据链**：事件层（硬事实）→ 片段层（证据本体，不可改）→ 固化层（片段哈希 + **外部可信时间戳**；本机自算哈希无效，自己改库就完了）→ 绑定层（片段 ↔ 单据/任务/操作人/设备）。**文字描述是派生出来的附加层，只能作检索辅助，不得作证据陈述。**

### 我给出的核心反方案（红队强制）

**「逐动作拆解」不该由视觉模型产出，应由系统事件拼装产出。**

- 用户要的「取件 → 扫码 → 封箱 → 贴单」：**扫码与贴单在系统里本来就是事件**（扫了什么码、打印了哪个面单，自带精确时间戳）；封箱可能有设备信号；只有"取件"无事件。
- ⇒ 动作序列 = **事件拼装 + 片段锚定**，视觉只负责"该时刻画面确实存在"。
- 对比：事件拼装零算力、硬事实、与私有化交付定位一致；视觉推断需 GPU（私有化不成立）或云 API（**跨境货主数据出境，撞定位**），且非受控场景准确率达不到举证级。
- **本方案的边界（我承认）**：事件层能证明"做过的动作"，证明不了"**没做的动作**"和"动作做得对不对"。这类只能靠人看片段 ⇒ 设计必须提供"按事件快速定位到某一秒"，而不是模型。

### 三处硬冲突

- **冲突 A（最硬，只有 Martin 能答）**：**视频画面天然违反约束 4（货主数据隔离）**。画面是**物理连续空间**，同一打包线/月台服务多货主时，A 的片段里必然拍到 B 的货与单据。2.4.1 已否掉"靠查询条件过滤"，而**画面不能按数据行过滤**。三条出路：① 物理隔离（上百货主不可能都划区）② 画面裁剪/打码（需视觉模型 + 空间映射，成本极高且不可靠）③ **合同 + 制度解决**（约定"共享作业区会被摄取、仅可调取与自身作业相关片段"，产品只做**调取授权与调取留痕**）。**我的判断：只有 ③ 可落地，但它是业态事实，必须 Martin 答。**
- **冲突 B**：强制视频关联撞**约束 9**（每个节点加动作）与**目标 B**（关联成为关键路径依赖，视频抖动即作业停摆）。**与 v10 反方 20「把加工放进出库关键路径」同构——同一类错误不能犯第二次。** ⇒ 设计必须是**异步、旁路、不阻塞**；关联失败 = 待补记录，不是作业阻塞。
- **冲突 C**：**私有化交付 vs 视觉大模型算力/数据出境**。**"生成描述"这一项与项目定位冲突，这正是不该走视觉路线的结构性理由。**

### 02-2 的实质内容

**两条骨架推论**：
- **推 2**：02-1 只有两个仓级口径位（计费集合 / 度量"满"），**缺第三个——上架裁决口径**。倾向不新增"选口径"字段（裁决本质是物理可行性判断，体积 + 承重固定），而是新增**降级顺序**。
- **推 7（最重要）**：规则配置单位是「货主 × 仓」= 上千组 ⇒ **仓级默认 → 货主模板 → 批量套用 → 例外覆盖**，且**继承关系必须可见**。与 02-1 §1.5 属性下沉规则构成一对矛盾：**下沉管"数据能表达多细"，继承批量管"配置动作有多少次"**。模板内容封闭清单五项。

**概念**：库容拆三层——空间容量（放得下）/ 占仓量（占多少）/ 库容效率（满不满）。**三者服务的目标、精度、时间粒度、可见性全不同，合并即撞约束 9。**

**四级硬约束校验**（把 02-1 已建字段接进算法）：库位容积 → 库位承重 → **区域承重（02-1 §2.6 第 11 项）** → **楼层承重 + 电梯运力**（01 §2.8.3「参与计算，不能当备注」）。**后两级最易漏——字段不在库位上。**

**两个模型判断**：
- **占用是投影不落表**，可物化。**判据 =「能否从源头重算出同一个结果」**：能 → 物化视图；不能 → 第二真相，必须退回投影。
- **库容 → 计费单向依赖**。红队（按费率排库位）有效但不在本域实现，只提供**权重插槽**。

**设计红线**：默认校验档 = **区域级**（库位错放可逆，强制扫库位码收益为负）；排序**只排序不求解、可关闭、可解释**（否则作业员停止思考，配错的权重会被规模化执行）。

**补的做假点**：除 01 §8 的"底面积算"外补两条——**② 已分配库位数 ÷ 总库位数（把库位划小划密就能刷高）**、**③ 容量参数偷改（改分母）→ 靠变更留痕挡**。

**反方 8 条**，第 1 条因 2026-09-17 画像输入而**反向重写**：原「画像未锁定、可能整体过度设计」已失效，真问题反过来了——**上千组配置动作让人配到崩溃**。
