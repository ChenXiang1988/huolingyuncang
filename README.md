# 货灵云仓

三方云仓仓储管理软件的**设计工作区**。私有化交付，买断 + 年服务费，不做 SaaS。一仓 N 货主，货权分离，重量款。作业方式为人工 + 手持终端，预留对接自动化设备的接口。

本工作区产出**交付物（文档与静态原型）**，**不含可运行代码**：没有后端、没有前端工程、没有构建脚本、没有自动化测试。下面各节按实际内容写，没有的部分直接写明「没有」。

### 3.1 `设计文档\`

文件名为 `编号-名称`。**编号是全库引用的锚，改文件名不得改编号：**

| 编号 | 身份 | 只回答 |
|---|---|---|
| `00-` | 过程档案与索引 | —— |
| `01-` | 业务蓝图 | 业态真相：业务必须如何运转 |
| `02-x` | 领域模型分册 | 模型结构：业务如何被结构化表达 |
| `03-` | 产品化切分表（**未建**） | 交付决策：先做什么、怎么切 |
| `04-` | 专题方案 | —— |

- `02-` 是一个**族**：`02-1` 仓库创建与基础定义 · `02-2` 库容管理 · `02-3`（编号已废，内容迁入 `表字段设计\货品域\货品档案.md`）· `02-4` 物流渠道 · `02-5` 账号与权限。
- `03-` 编号已预留但尚未落盘，故暂无 `05-`。
- **份内约束**：「一期 / 二期 / 优先级」这类交付期词只允许出现在 `03-产品化切分表.md`，出现在 `01` 或 `02` 里即身份错误。

### 3.2 `表字段设计\`

按域分子目录，**文件名＝表名、不带编号**：

| 位置 | 装的表 | 判据 |
|---|---|---|
| `货主域\` | `货主档案` | 描述「**谁**」 |
| `货品域\` | `货品档案` · `品牌主数据` · `货品名称多语言` · `货品属性值` · `品类主数据` · `品类属性模板` · `计量单位` · `单位换算率` · `货品证书` · `仓货品规则` · `账册商品备案` · `品类互斥矩阵` | 描述「**什么东西**」 |
| `单据域\` | `单据` · `单据关联` · `单据行` · `单据操作留痕` · `出库预报单` · `包裹面单` · `作业任务` · `集包单` · `交接单` | 描述「**一次业务动作**」——一张身份主表 `单据` ＋ 类型扩展表 |
| `仓库域\` | `物流渠道` · `拆单规则` | 描述「**仓的资源与配置**」——仓级，带仓标识、不带货主标识 |
| `账号域\` | `账号` · `角色` · `角色动作` · `账号授权` | 描述「**谁在用系统**」 |
| 目录根 | `00-表结构总览.md`（跨域索引，29 张表清单 · 外键依赖 · 建表顺序）· `行政区划.md`（跨域底座） | **跨域**，不随域走 |

判据是**对象**，不是归属：`货品档案` 的唯一键是（货主标识 + 货品编码）——本项目所有货品表本来就都是货主级数据，按归属分会装同一批表。

**四条须知**：

1. `货主档案` 同时是 `02-1` 的「主体」，仓的所属经营主体与货主位置引用同一张表。唯一键＝（证件类型 + 证件号码），**不是名称**。
2. **全局表不带货主标识**，不受数据隔离约束：`行政区划` · `品类主数据` · `品类属性模板` · `品牌主数据` · `计量单位` · `品类互斥矩阵`（6 张）。其中 `计量单位` 与 `行政区划` 的数据**来源不在本项目**（法定计量单位、GB/T 2260），系统只引用、不自造。`品牌主数据` 另有禁令：禁止按品牌做跨货主聚合或反查。另有 2 张既不带货主标识、也非全局——`物流渠道` · `拆单规则`（仓级）。
3. `货主域\` 现只 1 张表，且 `货主档案` 本体字段薄；货主侧的商务表（合同 · 计费规则 · 服务等级承诺 · 数据可见性授权 · 库容配额 · 影像调取授权）**尚未建**。
4. `仓货品规则` 与 `账册商品备案` 是交叉表，主语分别是仓与账册，按「内容是货品的扩展」归入 `货品域\`。

### 3.3 `原型\`

```
原型/
├── 设计规范.html            # 样式基准，18 节 + 反方审查 + 未决项
├── 00-资源/原型样式.css     # 公共样式，628 行
├── 01-货主端/               # index.html 为端入口
├── 02-云仓管理端/
├── 03-单仓端/
└── 04-手持端/
```

- 目录用 `编号-名称`，连接符不含空格，新增端从 `05-` 起。文件命名＝页面名.html，不带编号。
- **每端 `index.html` 是本端入口**，含「页面索引与依据」表，逐页登记上游条款。
- 页面一律外链 `../00-资源/原型样式.css`，不写页内 `<style>`；脚本只允许内联，且**只限四类**：登录页表单校验 · 弹出提示的静止判定 · 管理端新建 / 编辑表单页的表单校验 · 登录态与权限显隐（仅限云仓管理端，读不到登录态时一律全量显示）。
- 配色口径全部取自 Ant Design 官方 Design Token；三端管理后台统一为 `navTheme:'light'` + `layout:'side'` 且不做多页签栏，**手持端不适用该规范**。
- **`设计规范.html` 第一节是「原型表达的简洁原则」**：除非确有必要，否则不添加额外的解释性内容。判据看内容服务谁——服务使用者的留（做成界面元素本身），服务评审者的出（归规范页或 `index.html`）。

## 七、编写规范要点

### 7.1 约束在哪

| 文件 | 管什么 | 何时读 |
|---|---|---|
| `CODEBUDDY.md` | 跨目录、对话级最高约束：项目定位 · 对抗性审查 · 文档身份纪律 · 协作规则 · 篇幅口径 · 文件治理 · AI 操作纪律 · 交接机制 · 约束效力 | **动手前必读** |
| `.codebuddy\rules\设计文档体例.md` | `设计文档\` · `表字段设计\` 的施工口径 | 改这两类文件前 |
| `.codebuddy\rules\原型体例.md` | `原型\` 的目录与命名、样式同步、技术约束 | 改原型前 |

`设计文档体例.md` 与 `原型体例.md` 是**条件规则**（`paths` ＋ `alwaysApply: false`），不匹配路径时不加载、也不报错——不能假定它一定在上下文里。

### 7.2 文档头部

四份设计文档的头部字段集合相同（项目 · 身份 / 性质 · 范围 · 上位依据 · 日期），**但顺序不统一**。**改头部时沿该文件既有顺序，不跨文件统一。** 上位依据必须标 `01` 的版本号，格式 `` `01-业务蓝图.md` **v12** ``。

### 7.3 锚点引用语法

| 写法 | 指什么 |
|---|---|
| `01 §2.3` | 文档编号 + 节号 |
| `02-1:106` | 文件行号 |
| `02-1 §3.3 C3b` | 节号 + 条款编号 |
| `场景 7` · `反方 19` · `推论 2.5.5` · `01 约束 4` | `01` 的场景 / 反方 / 推论 / 约束编号 |
| `U17` · `W8` · `Q4` · `V3` · `D13` | 未决项编号，按文档分配（`01`=U · `02-1`=W · `02-2`=Q · `02-4`=V · `04`=Q · `参考资料`=D）。**跨文档引用必须写全**（如 `02-2 Q4`） |

**改条款序号会断全库引用**——必须先搜出全部引用一并改。

### 7.4 协作与交付口径

1. **文件治理**：只生成当前任务必需的文件；新增文件须先说明理由并等确认，不得先建后报。脚手架、示例资源、演示数据一律不建。
2. **先说明白再动手**：方案先讲清，等拍板；拍板的词是「落地」。
3. **原文零改写**，不做工期承诺，全中文。
4. **对抗性审查**：蓝图 / 领域模型 / 需求方案 / 原型说明四类 Markdown 交付物末尾固定「反方审查（≥5 条）+ 未决项」。禁止软化措辞；红队不得编造业态事实。
5. **禁止在同一消息里对同一文件发多个编辑操作**——并行读改写会互相覆盖。改多处用一次性补丁脚本。
6. **交接机制**：说「交接」即在 `交接记录\` 落一份七节结构的状态快照；记录只指向文件、不复述正文。
7. **AI 操作**：动手前列全工作区文件并读最新内容；批量替换先限定范围、先备份，替换后立刻比对总量指标。

## 九、反方审查

1. **这份 README 在描述一个不存在的软件。** 工作区里没有一行产品代码，所谓「核心功能」是文档里写的业务功能，不是可交付、可验收的功能。要接手的人照它去 `npm run dev` 一定会失败——这一条我反驳不了，接受：README 的定位应当写成「设计工作区导览」，而不是「项目说明」。
2. **「技术栈」一节会误导。** 写了 Ant Design Token 与 Git，读起来像有前端工程，实际样式的唯一载体是一份 628 行的手写 CSS，颜色靠人肉对齐。改动一旦超过一定页数，_token 一致性_ 无法维持。
3. **「无测试、无 CI」是现存最大风险。** 61 个原型页靠侧栏导航互链，任何改名或移动目录都会断链；上次目录改名已触发 58 个文件的路径改写。没有自动化检查，靠人工逐页点过去。
4. **「29 张表」的边界尚未稳定。** 建域判据是 2026-09-26 才补的，账号域就是这套判据新增的第一个域；下次出现新对象（结算、计费、核算）是否再扩域，没有判据可依——README 现在写下的分类会被当成已定事实。
5. **`01` v12 与三份下游文档的 v11 不一致，README 却按 v12 写。** 下游依赖的是旧版，本文描述的「上位依据」关系名不副实。
6. **「配置项：无」看起来像没写完。** 真实原因是这个项目还没到配置阶段——配置表会在交付切分时才有意义，现在写等于替 `03-产品化切分表`（未建）做决定。
